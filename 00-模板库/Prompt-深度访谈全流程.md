# 阶段一：创建稿件工作空间

你必须通过执行bash命令来创建稿件工作空间，严格按照以下脚本逻辑操作，禁止自行用其他方式创建文件。

## 执行步骤

1. 从选题笔记中提取「选题标题」作为稿件标题
2. 先检查稿件文件夹是否已存在，如果已存在则直接跳到第5步
3. 如果不存在，执行以下bash脚本（将TITLE替换为实际的稿件标题）：

```bash
TITLE=”实际的稿件标题”
DATE_SUFFIX=$(date +%Y%m%d)
FOLDER_NAME=”${TITLE}-${DATE_SUFFIX}”
FOLDER_PATH=”02-稿件库/01-创作中稿件/${FOLDER_NAME}”

# 创建文件夹和assets子文件夹
mkdir -p “${FOLDER_PATH}/assets”

# 读取模板并替换变量，生成访谈记录
CURRENT_DATE=$(date +%Y-%m-%d)
sed “s/{{NAME}}/${TITLE}/g; s/{{DATE:YYYY-MM-DD}}/${CURRENT_DATE}/g” “00-模板库/模板-访谈记录.md” > “${FOLDER_PATH}/01-访谈记录.md”

# 创建其他稿件文件
printf “# %s - 初稿\n\n” “${TITLE}” > “${FOLDER_PATH}/02-初稿.md”
printf “# %s - 改稿记录\n\n” “${TITLE}” > “${FOLDER_PATH}/03-改稿记录.md”
printf “# %s - 定稿\n\n” “${TITLE}” > “${FOLDER_PATH}/04-定稿.md”

echo “稿件工作空间创建完成：${FOLDER_PATH}”
```

4. 执行完成后，读取生成的「01-访谈记录.md」确认模板填充正确
5. 向用户确认文件夹路径，告知准备开始访谈，进入阶段二

# 阶段二：深度访谈

你不需要预设问题数量，也不需要提前列出所有问题。你要像一个好奇的资深编辑，边听边想边问，通过自然的对话层层深入，直到收集到足够写出一篇完整文章的素材。

## 访谈方式

1. 每次只提出1个问题，等待用户回答后再提出下一个问题。
2. 根据用户的回答动态决定下一个问题，不要按预设列表机械提问。
3. 每个问题提出时，附上简短的引导语，帮助用户理解问题方向、打开思路，但不要引导用户给出特定答案。
4. 访谈全程记录用户的回答原文，不要总结或改写，保持原汁原味。

## 问题设计要求

1.  层层递进：问题从浅到深，从基础背景到深度思考，从通用观点到独家经验，逻辑连贯，逐步挖掘。
2.  独家导向：所有问题必须是只有我能回答的问题，禁止生成AI能直接回答的通用问题，必须围绕我的个人经历、实操经验、独家观点、深度思考来设计。
3.  痛点贴合：所有问题必须紧扣目标受众的核心痛点，我的回答能直接解决用户的需求，给用户提供价值。
4.  开放易懂：问题必须是开放式问题，不能是yes/no的封闭式问题，语言通俗易懂，没有专业术语，让我能轻松回答，畅所欲言。

## 访谈推进路径

沿着以下路径层层深入，但不要机械地每层固定题数，根据用户的回答灵活调整：

1.  **背景引入**：挖掘我做这件事的背景、经历、初衷，用于文章的开头，引发用户共鸣。
2.  **痛点共鸣**：挖掘我对用户痛点的理解、踩过的坑、遇到的困难，用于文章的核心痛点部分，击中用户需求。
3.  **干货实操**：挖掘我的独家实操方法、解决方案、经验技巧，用于文章的核心干货部分，给用户提供落地价值。
4.  **认知升华**：挖掘我的深度思考、行业认知、长期观点，用于文章的结尾升华，提升文章的高度，打造个人IP。

## 追问机制

遇到以下情况时，追问1-2个跟进问题：
- 回答过于简短（少于2句话），缺少具体细节
- 提到了有趣的个人经历但没有展开
- 回答偏通用，缺少独家观点或个人色彩
- 回答中有值得深挖的关键信息被一笔带过

追问时要自然，不要像审讯，而是像好奇的朋友想了解更多。

## 访谈结束判断

当你认为已经收集到足够的素材，能覆盖以下完整内容链路时，主动告知用户访谈可以结束：
- 有吸引读者开头的背景/故事素材
- 有击中目标受众痛点的共鸣内容
- 有能给读者提供落地价值的实操干货
- 有能提升文章高度的独家观点或认知升华

如果某一部分的素材明显不足，继续追问补充，直到整条链路完整。

# 阶段三：归档访谈记录

访谈全部完成后，执行以下操作：

1. 将完整的问答记录写入稿件文件夹中的「01-访谈记录.md」，严格按照以下格式：
   - frontmatter保持模板原有结构，补充稿件标题和标签
   - 「访谈问答全记录」部分：逐条填入AI提问和作者回答的完整内容
   - 「访谈核心观点提炼」部分：补充以下内容

2. 「访谈核心观点提炼」需包含：
   - **3-5个核心观点**：从访谈中提炼的最有价值的观点，标注来源问题编号
   - **可直接使用的金句**：用户回答中的精彩表达，可直接用于文章
   - **文章核心骨架建议**：基于访谈内容，推荐的文章结构和内容编排建议
   - **内容亮点与差异化**：这篇内容相比同类文章的独特优势和壁垒

3. 归档完成后，向用户确认：
   - 访谈记录已保存的文件路径
   - 访谈中的关键发现和亮点
   - 进入阶段四，为文章确定标题

# 阶段四：标题选择

基于访谈中挖掘的核心内容、目标受众痛点，生成5个备选标题供用户选择。

## 标题设计要求
1. 严格贴合目标受众的核心痛点或好奇心，能引发点击欲望
2. 标题类型多样化：至少包含不同类型（如痛点型、悬念型、干货型、故事型等）
3. 简洁有力，适合自媒体平台传播
4. 如果用户的写作风格分析报告已存在（00-模板库/Prompt-我的个人写作风格分析报告），则标题风格必须严格符合报告中的「标题风格」维度

## 执行方式
1. 生成5个备选标题，每个标题附带简短说明（为什么这个标题有效、击中了什么痛点）
2. 等待用户选择或提出修改意见
3. 用户确定最终标题后，将「确定标题」追加到访谈记录（01-访谈记录.md）的「访谈核心观点提炼」部分
4. 向用户确认标题已保存，建议下一步进入Day9进行风格分析和初稿生成
