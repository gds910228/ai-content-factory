## 一、选题核心背景与用户痛点

**背景**：[[模型越来越强， harness该留下什么？|腾讯团队的 harness 瘦身实录]]给出一个颠覆性框架：**"harness 里的每一个组件，都编码了一个关于'模型自己做不到什么'的假设"——你写的每条 Prompt，都在赌一件模型做不到的事，而赌注会随模型变强陆续到期。**铁证：Anthropic 删掉 Claude Code 系统提示词 80% 以上，编码评测无可测量损失；存在多年的 prefill 技巧从 API 层直接移除；官方明确指出"为旧模型写的指令，在新模型上会主动造成质量损失"——冗余从"浪费 token"升级为"缩小模型搜索空间的净损失"。

**目标受众的核心痛点**：
1. **CLAUDE.md/AGENTS.md 只增不减**：每遇到一次 AI 翻车就加一条规则，文件越来越长、效果越来越差、且谁也不敢删——因为说不清每条防的是什么。
2. **规则写了不听**：写了"保守一点""只报高危问题"，AI 反而表现更差（照字面执行、削减召回）。
3. **不知道该写什么**：听说"要精简"，但到底哪些该删、哪些必须留，没有判据。
4. **官方文档读不懂**：Anthropic/OpenAI 新版 prompting 指引是英文的、面向企业，初级开发者缺一份"翻译+可照做"的版本。

> 一句话：把"每条 Prompt 都是赌注"的框架 + 官方新版指引，翻译成个人开发者的 Prompt 自查改造手册。

## 二、选题核心切入角度（3个以上）

1. **"你的规则文件为什么只增不减"开场**：直击现象——不是懒，是"这些规则当初就没写清防的是什么，所以谁也不敢删"。引用原文金句："说不清防什么的规则，从写下来的那一刻就已经无法被淘汰了。"
2. **"到期赌注"识别清单**：翻出你规则文件里的任意一条，问它"为什么存在"——理由是"模型记不住/不会主动做/容易漏"的，全部已在到期队列（context resets、任务分片、prefill、CoT 诱导、CRITICAL 强调语都是真实到期的案例）。
3. **"规则→判据"改造法（核心干货）**：用官方 before/after 对照讲透——穷举式禁令换成一条判据（注释风格案例），MUST/NEVER 只留给"真正的不变量"（不可逆动作），判断题一律改写成决策规则。
4. **【独家观点】"绑失败模式"是唯一的防身术**：每写一条规则，就绑定它防御的那个具体失败（"它在第三步漏掉了 X"而非"效果不太好"）——这样模型进化到不再犯这个错时，你有明确信号可以删。这是"面向未来写 Prompt"唯一可执行的形态。
