## 一、选题核心背景与用户痛点

开发者经常怀疑"我的 Prompt 是不是该优化了"，但缺乏判断标准——**不知道多长算太长、不知道哪里出了问题、不知道该重构还是继续加规则**。痛点是"无法自检"带来的持续低效与反复踩坑：每次出问题就加一条规则，越加越乱却说不清"乱在哪"。

素材结尾给出一份 7 问检查清单，把模糊的"感觉有问题"变成可操作的诊断工具，是高收藏价值的工具型内容。本选题把"诊断 + 开方"打通，让读者不止于发现问题，还能拿到修复动作。

## 二、选题核心切入角度（3个以上）

1. **7 问自检清单逐条解读**：① Skill 超过 500 行了吗（该分拆外置）；② 最关键禁令是否在前 10%（不在就移上去）；③ 有无隐性冲突的规则（逐对检查"合理推理出错误行为"的空间）；④ 同一规则重复超 2 次吗（说明架构有问题，不是强调不够）；⑤ 参考内容和规则分开了吗；⑥ 参考文件和规则一致吗（模板有无被禁字段、示例是否完整覆盖）；⑦ 自动修复有"刹车"吗。
2. **自检 → 行动映射**：每条问题对应一个具体修复动作（如超 500 行 → 进重构模式而非追加；重复超 2 次 → 合并到开头），让清单不止于"诊断"还能"开方"。
3. **技术债类比**：把 Prompt/Skill 维护类比为代码技术债——每次 hotfix 都在堆债，不定期重构就会腐化。借程序员熟悉的认知降低理解门槛，呼应独立开发者受众。
4. **防膨胀机制参数化**：行数预算、语义去重、单次追加上限（≤ 20 行）、定期压缩（每 N 次强制全局审视合并），给"刹车"具体可执行参数。

## 四、Claude AI选题评估与建议

- **传播性：高（收藏型）。** 清单类内容天然高收藏、高转发（"先马后看"），算法友好，适合沉淀长尾流量；痛点普适。
- **落地性：极高。** 清单即工具，读者可直接拿来用；可做成图文/卡片高传播。
- **竞争度：低。** 系统化的 Skill 健康度自检清单稀缺，多数是零散技巧；本清单 7 问成体系、可落地。
- **创作建议**：做成"可收藏的卡片式清单"提升传播；与痛点篇、方法论篇组成系列（理解原因 → 掌握方法 → 自检落地）闭环；可作为涨粉/留存的主力干货，是 Top 2 优先创作之一。
