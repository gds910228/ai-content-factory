## 一、选题核心背景与用户痛点

用AI写代码最让人崩溃的体验之一：你花了半小时给AI解释你的项目架构、业务逻辑、技术栈，它终于理解了，开始写出不错的代码。结果第二天你打开新对话，一切归零，又得重新解释一遍。

这就是Anthropic总结的"Cold Start Problem（冷启动问题）"——多次会话间缺乏持久化记忆，每次新会话需花大量Token重新理解项目结构，真正用于编码的Token被严重挤压。

更深层的问题是上下文管理：你把所有信息一股脑塞给AI，它反而更糊涂了。信息源中提到，上下文窗口填充率超过40%后，AI输出质量快速衰退。

## 二、选题核心切入角度（3个以上）

1. **痛点场景还原角度**：还原"每天重新解释项目"的崩溃场景，用具体对话示例展示Token浪费和效率损失。引用Anthropic的"Cold Start Problem"让读者知道这是系统性问题。
2. **三层上下文管理法角度**：将信息源中的分层加载策略简化为独立开发者可用的三层方法：
   - L1 常驻层：每次对话必加载（项目简介+核心规则，控制在100行以内）
   - L2 按需层：进入特定任务时加载（编码规范、API文档等）
   - L3 查询层：AI需要时自己去查（业务细节、历史记录等）
3. **实操模板角度**：给出一个CLAUDE.md的最小化模板，包含：项目背景（20行）、规则索引（10行）、关键约束（10行），总计控制在40行以内。强调"做地图，不做百科全书"。
4. **持久化记忆方案角度**：介绍用progress.md/summary.md文件实现跨会话记忆的方法——每次结束前让AI更新进度文件，下次对话开头读取进度文件继续工作。
