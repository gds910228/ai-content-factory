## 一、选题核心背景与用户痛点

**选题缘起（真实需求触发）**：这周有朋友（公司同事 fighting!）问我："Archer，你们目前用的啥设计稿呀？这边公司想实现一个完整的 AI 从稿件到落地的实践，想看看有哪些比较好的工具。"他领导想要全程 AI Coding，并让他总结经验。这是一个极具代表性的需求——**大量团队和个人都想"全程让 AI 写代码"，却完全不知道从何下手、怎么保证质量**。

**目标受众的核心痛点**：
1. **裸用 Agent 必翻车**：直接让 AI 写代码，"语法正确、风格统一，但业务语义微妙出错"——用了项目不存在的框架、改一个文件搞坏另一个功能、"改下样式"变成重写整个页面。初级开发者以为是模型不够聪明，其实是没告诉它"在什么环境里、按什么规则工作"。
2. **听说 Harness 却不会落地**：Harness Engineering 是 2026 AI Coding 最火概念，但网上文章要么偏入门科普（一川版），要么偏企业级深度实践（新安·阿里版），**缺乏"独立开发者视角、能直接照做的实操心得"**。
3. **不知道"什么时候该用"**：简单 demo 用 Harness 是过度工程、白烧 token；大项目不用又失控。读者缺一个"何时用、怎么用、用多重"的判断框架。
4. **搭建路径迷茫**：是从零手撸，还是用 Harness Creator skill 快速生成？两条路怎么选、怎么打磨？

> 一句话：这个选题击中的是"想全程 AI Coding 却翻车/无从下手"的群体性焦虑，而我能用亲身实操给出答案。

## 二、选题核心切入角度（3个以上）

1. **真实对话开场，代入"公司想全程 AI Coding"的普遍困境**：用与朋友 fighting! 的聊天记录作为引子，自然带出"Harness 是当前 AI Coding 的最佳实践"，从真实需求切入而非空谈理论，第一时间建立代入感。

2. **【独家反共识观点】Harness 不是越强越好，要看项目规模**：这是我实操后的真心话——简单项目/demo 在强模型（如 GLM5.2）面前压根不需要 Harness，那些"看起来很规范"的约束反而是 token 消耗；只有巨大代码量项目才必须用，本质是"受限于模型推理能力和上下文空间"的折中手段。**这是区别于全网"无脑推崇 Harness"同质化文章的核心记忆点。**

3. **实操心得：两条搭建路径的取舍**：
   - **捷径**：安装 Harness Creator skill，让 Claude Code 照着生成，对照阿里那篇文章，再根据个人经验和项目实际打磨 MD 细节；
   - **进阶自定义**（相当于"以前手撸源码"）：先从 superpowers skill 里挑所需 skill，再让 AI 读阿里文章、提取搭建 SOP，然后搭建其余 MD 文件。
   - 我前期在**图片处理 MP、旅游民宿 MP、游戏站点**三个项目用的是自定义搭建，没用 Harness Creator skill——这是真实取舍经验。

4. **落地 SOP 拆解（可截图带走的清单）**：基于我的《Harness 落地设计 SOP》12 个环节（前置摸底 → 搭建 .harness/ 骨架 → Rules → Skills → Application Owner Agent → Wiki → L1/L2/L3 上下文分层 → 十阶段流程 → 变更管理 → MCP → Dry Run → 持续迭代），讲清独立开发者如何为自己的项目从零落地 Harness，强调"Dry Run 先空跑""质量门禁必须可程序化验证""每发现一个错误就工程化消除"。

5. **认知升级收尾：AI Coding 就是面向文档编程**：从我 2025 年 3 月用 Cursor 接触 Vibe Coding 讲起（rule.md / dev.md / prd.md 就是 Harness 雏形），串联 Prompt → Context → Harness 三次范式跃迁，并引出四种 Loop Engineering 循环思路，给读者一个"历史脉络 + 未来方向"的认知闭环。
