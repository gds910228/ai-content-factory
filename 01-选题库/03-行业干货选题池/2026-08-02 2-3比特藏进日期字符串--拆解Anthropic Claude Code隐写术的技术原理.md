## 一、选题核心背景与用户痛点

**背景**：与热点篇同一事件，但本篇聚焦"它到底是怎么做到的"。Anthropic 在 Claude Code 中用一套组合拳实现隐蔽追踪：① 读取本地时区与 `ANTHROPIC_BASE_URL`；② 用 base64+XOR（密钥 91）加密一份 147 个国内域名列表做比对；③ 把识别结果编码成 2-3 比特，通过修改系统提示词里日期字符串的标点（单引号 U+0027 换相似 Unicode 字符、连字符改斜杠）悄悄传回服务器。

**目标受众的核心痛点**：
1. **"原理黑箱"焦虑**：看了新闻只知道"被追踪了"，但 base64+XOR 是什么、2-3 比特怎么编码、为什么改个标点就能传信息--完全不懂，信息差带来不安全感。
2. **想学无从下手**：信息安全/隐写术对初级开发者像另一个世界，缺一个"用真实案例入门"的抓手。
3. **判断力不足**：不懂原理就无法判断"这事严不严重""会不会被滥用""我自己能不能复现验证"，只能盲信媒体结论。

> 一句话：把一个真实的大厂隐写术案例拆成可理解的零件，让初级开发者第一次"看懂"信息隐藏是怎么回事。

## 二、选题核心切入角度（3个以上）

1. **"密钥 91 的秘密"**：拆解 base64+XOR 加密的 147 域名列表，演示密钥 91 是怎么参与异或、如何还原明文，把"加密域名列表"这件听起来神秘的事讲成可复现的小实验。
2. **"单引号里藏暗号"**：讲 Unicode 替换机制--U+0027 会被换成哪些肉眼难辨的相似字符、为什么人眼看不出、2-3 比特如何映射成有限分类标记。
3. **"服务器怎么读回来"**：还原请求链路，服务器如何从被改写的日期字符串里反推出用户分类，把"客户端藏、服务端取"的闭环讲清楚。
4. **"为什么偏偏选日期字符串"**：分析选这个载体的精妙--必现、低风险、不破坏功能、肉眼无感，是一堂"载体选择"的隐写术设计课。
5. **【独家观点】"隐写术不是黑客专利，是产品埋点的极端演化"**：把这次事件放进"产品埋点从可见 cookie 到隐蔽字符"的演化线里，指出它的危险不在技术而在"隐蔽性"违背了用户知情权。
