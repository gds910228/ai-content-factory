## 一、选题核心背景与用户痛点

**背景**：与实战篇同一素材，但角度从"用"转到"造"。把"做个清理 skill 替代 CleanMyMac"作为案例，拆解从需求识别到开源发布的 AI Skill 开发全流程：原作者用 Codex 做只读分析、设计三色分级（绿/黄/红）、用可交互 HTML 报告作交付、跨平台支持、实测释放近 120G。

**目标受众的核心痛点**：
1. **想做 skill 不知道从哪起步**：需求怎么定、边界怎么画、安全怎么保证，没有完整范式可循。
2. **涉及文件操作就怕出事**：清理类 skill 一旦删错文件就是灾难，不知道怎么设计"不删错"的护栏。
3. **做完不会发布**：开源到哪、README 怎么写、怎么从"自己用"到"被人用"，缺最后一公里。
4. **入门项目难找**：想练手却找不到"小而完整、能解决真实痛点"的 skill 案例。

> 一句话：用一个"清理电脑"的真实案例，把 AI Skill 从需求到开源的完整造法走一遍，给初级开发者一个能照抄的范式。

## 二、选题核心切入角度（3个以上）

1. **"需求识别"**：怎么从"不想花 120 刀"这个私人痛点，提炼成一个边界清晰、可做的 skill 需求--讲清"好需求"长什么样。
2. **"安全边界设计"**：以三色分级为例，讲 skill 涉及文件操作时怎么设计"不删错"的护栏--只读扫描优先、人工确认兜底、红灯绝对禁止，这套思路可迁移到任何危险操作类 skill。
3. **"交付物设计"**：为什么选可交互 HTML 报告而非直接执行，讲"AI skill 的交付是信息不是动作"--这个判断能重塑读者对 skill 的理解。
4. **"开源发布最后一公里"**：从代码到被人用的步骤--README、demo 截图、发布渠道、版本管理，讲清"做完"和"被人用上"的差距。
5. **【独家观点】"最好的 skill 入门项目，是解决你自己一个具体的小痛点"**：反对"为练手而练手"，主张从真实痛点入门，作品才有灵魂、才能开源获客。
