## 一、选题核心背景与用户痛点

**背景**：一个月内，两篇不同大厂团队的内部实操长文先后入库：腾讯 tdsql-harness 团队删掉框架 61% 后的反思（[[模型越来越强， harness该留下什么？|模型越来越强，harness该留下什么？]]，08-06）与淘天交易团队的 AI Coding 战略思考（[[01-选题库/03-行业干货选题池/我对 AI Coding 的一点思考：从 Spec 驱动转向环境与验证驱动|从 Spec 驱动转向环境与验证驱动]]，08-24）。两篇互不引用、视角不同（一个微观做减法、一个宏观做加法），却**独立收敛到了同一条投入分界线**：凡是补偿模型能力缺口的投入（提示词、编排、脚手架）都会被下一代模型吸收作废；凡是模型自己造不出信息的地方（环境、验证、私有上下文、责任边界）才是持续增值的自有资产。

**目标受众的核心痛点**：
1. **信息过载难辨方向**：大厂文章、KOL 观点满天飞，初级开发者缺乏"合并同类项"的能力——看不出散落各处的说法背后是同一件事。
2. **不知道大厂经验对个人有什么用**：企业级实践（tdsql-harness、内部平台）看似遥远，读者需要"翻译者"提炼出可迁移的部分。
3. **怕站错队**：跟风学的框架/技巧被淘汰的失落感（Superpowers 热度的退潮正在发生），需要一个跨源验证的判断锚。

> 一句话：两家大厂从相反方向算出了同一道题——这道题的答案，个人开发者可以直接抄。

## 二、选题核心切入角度（3个以上）

1. **"双盲实验般的收敛"叙事开场**：两个团队、一个做减法（删 61%）、一个做加法（建环境），却画出同一条分界线——这种独立性本身就是结论可信度的最强背书。
2. **对照表拆解（核心结构）**：逐条对齐两篇的"同构判断"——腾讯"补能力缺口的都会过期" ↔ 淘天"替代推理能力的会被吸收"；腾讯"L2/L3 信息源头在人" ↔ 淘天"关于世界的信息只能从世界里来"；腾讯"验证类 skill 影响最大" ↔ 淘天"可验证反馈决定能力边界"。
3. **乘法公式的个人版翻译**：淘天"红利=模型能力×环境能力"（模型是租来的因子、环境是自有因子）——对个人开发者：模型人人可用，你的 skills 库、验证脚本、项目上下文才是那个"自有因子"。
4. **【独家观点】"个人开发者的环境就是他的公司"**：大厂改造内部平台，个人改造自己的工具链——两者在"把只有自己能操作的东西变成 AI 可调用的"这个动作上完全等价。个人站、小程序、发布管线（呼应 Xpert 副业的反哺飞轮）就是个人的"内部系统工具化"。
5. **趋势佐证收尾**：连 Anthropic 自己都在做（Claude Code = 模型厂商的自建 harness，删到 20% 后留下的全是环境与验证）——"连造模型的人都在赌这边，你还在犹豫什么"。
