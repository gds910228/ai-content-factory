## 一、选题核心背景与用户痛点

进阶痛点：随着 Agent 能力扩展，Prompt/Skill 越写越长，几百上千行难以维护，模型反而"读不动"、频繁出错。开发者想精简却不知从何下手——**哪些该留、哪些该外置、规则放哪个位置**。

素材给出工程化答案：把 Skill 当作有层次结构的文档，**"位置即优先级"**。作者将 Skill 从 1500 行精简到 300 行（减 80%），遵循率反而上升。本选题把零散的解法整合成一套可照做的"重构方法论"，解决"想精简无从下手"的进阶痛点。

## 二、选题核心切入角度（3个以上）

1. **分层架构——位置即优先级**：4 层结构（① 全局不可违反规则，最前 20–50 行；② 核心方法论；③ 执行流程，中间区域允许适度遗漏；④ 输出模板，末尾利用近因效应）。全局禁令只在第 1 层写一次，后续只引用——禁令置顶利用首因效应（遵循率最高区）。
2. **外置知识给 Skill 减负**：区分"规则类（行为约束，留 Skill）"与"参考类（表结构/SQL 模板/报告格式，外置为引用文件）"，让 Skill 保持在 300–500 行"甜区"，把注意力预算留给真正重要的约束。
3. **参考文件一致性——别让"课本"和"规则"打架**：外置后易出现模板 SELECT 了被禁字段、示例只覆盖部分维度等问题，模型在"听规则"和"照模板"间反复横跳。修复原则：彻底删除被禁内容（注释也不行，注释也是 token）、示例必须完整覆盖、关键格式差异放显眼对照表。
4. **指令三明治**：对最关键 2–3 条规则在首尾各放一遍（首因 + 近因效应），区别于无序的中间堆砌——有意识利用注意力高峰，而非到处重复。
