## 一、选题核心背景与用户痛点

**定位：系列"根因篇 / 元凶篇"，补 ①③⑤ 留下的暗线。**

系列已有三篇（①恶性循环 / ③分层重构 / ⑤自检清单）都默认一个前提：**是你在亲手维护 Skill**。①讲你亲手"再强调一遍"如何制造恶性循环，③讲怎么分层重构，⑤讲怎么自检。但有一类进阶开发者做了另一件事——把维护外包给"自动修复工具"：发现 badcase 就喂给工具，让它自动分析、生成规则、更新文档、发布。看似高效，实则把①里那个恶性循环交给了不会累、不会烦、没有"懒得再敲一遍"念头的执行者：油门踩到底，刹车全拆。

结果：几十轮后 Skill 面目全非，同一条规则散布 8 处，"严禁""铁律"层层加码，违反反而更多——和①一模一样的症状，但**元凶变了**：不是你的强调惯性，而是**工具的勤勉追加**。更危险的是，因为每次 diff 都很小、看起来都"正确"，你压根察觉不到膨胀正在发生。①是"听得见噪音的恶性循环"，④是"静音的恶性循环"。

痛点定位：**"自动化移除了天然刹车"**。人手改 Skill 时，人的懒惰反而是膨胀的刹车；自动修复把它拆掉了，每次 badcase 都被勤勤恳恳地转化为新规则。这是用 Cursor / Claude 等 AI 工具自动迭代 Prompt 的开发者极易踩中、且几乎无人系统讨论的隐性陷阱。

## 二、选题核心切入角度（3个以上）

1. **揭穿元凶：自动修复工具是"膨胀引擎"，不是"修复引擎"**（主线）——工具为何总选"再写一遍"。4 个结构性短板：① 局部视角 vs 全局视角（难对长文档做全局语义扫描）；② "安全追加"偏好（追加比改中间段落更常见、更安全）；③ 没有"文档健康度"概念（不知最优长度、不知重复是坏味道）；④ 自动化移除了天然刹车。**定调**：这是当前 LLM 在"改长文档"上的结构性短板，换更好的工具也治不好——答案不是"换个工具"，而是"给工具加约束"（具体配置见⑤，本文不展开）。
2. **"勤勉的灾难"：自动化拆掉了天然刹车**——把④独占的洞察拎成主线：人手改时，"懒得再敲一遍严禁"是天然刹车；自动改时，工具没有懒惰、只有勤勉。对照"人手改 vs 自动改"：人会累、会嫌烦、会怀疑"这条是不是写过了"，工具只会忠实追加。每次 diff 都小且"正确"，于是膨胀静音发生——温水煮青蛙。
3. **膨胀过程量化还原**（本文独占，①③只用端点数字）——用 git 历史四阶段表还原"怎么一步步长胖的"：初版 ~400 行 → +10 次 ~650 行 → +25 次 ~1000 行 → +40 次 ~1500 行，同一规则最多散布 8 处。40 次追加约 1100 行、平均每次 27 行、真正新知识仅约 300 行、重复约 800 行——每次都是"一小段"，累积就是原文 2.75 倍。让读者看见"勤奋的复利"。
4. **决策树还原：单个 badcase 上，工具做了什么 vs 该做什么**——现实路径：读 badcase 描述 → 生成一段新规则 → 找个"相关"位置插入。理想路径：通读全文 → 找已有规则 → 分析根因（措辞不清？位置不对？还是冲突？）→ 最小化修改。逐节点对照，让读者看清"每一步都局部合理、整体却是灾难"——这正是结构短板比 bug 更难治的原因。
5. **普适警示：不只 Prompt**——任何基于"提取经验 → 自动追加规则"的反馈系统，不加约束都会重蹈覆辙。可映射到 RAG 知识库（检索 Badcase → 自动塞新文档）、规则引擎、自动化运营策略库。把一篇工具文升格为"反馈系统设计警示"，提升格局。

## 四、Claude AI选题评估与建议

- **传播性：中。** "规则写了 8 遍""自动修复翻车"有画面感和故事性；但"自动修复工具"对没用过的读者有门槛，受众偏进阶。开篇可用"你以为是工具帮你修 bug，其实是工具在帮你堆债"的反差钩子。
- **落地性：高。** 决策树对照（现实 vs 理想）可直接做成自查清单；刹车配置虽不在本文展开，但结尾指针 ⑤ 形成转化闭环。
- **竞争度：低。** 几乎无人系统讨论"自动化迭代 Prompt 的膨胀陷阱"；把元凶从"模型"转到"工具"、并上升到"反馈系统设计警示"，角度稀缺、壁垒高。
- **创作建议**：
  - 定位为系列**"根因篇 / 元凶篇"**，承接 ①（手动恶性循环）→ ④（自动化恶性循环，且静音）→ ③⑤（治法与自检）。开篇一句话定调："前面三篇都假设是你在亲手维护 Skill——但如果你把维护交给了自动修复工具，元凶就变了。"
  - 全文压在"工具为何总选再写一遍"的机制拆解 + 量化故事 + 系统性警示上；刹车机制**降级为结尾一句指针**（"具体刹车配置见⑤，这里不重复"），避免与 ⑤ 撞车。
  - "人手改 vs 自动改"对照表 + 单 badcase 决策树对照，是本文两个最值得配图的视觉锚点。
  - 受众偏进阶，适合发在偏技术的公众号"AI启蒙学习"。
