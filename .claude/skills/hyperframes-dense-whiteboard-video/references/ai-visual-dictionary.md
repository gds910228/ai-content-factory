# AI 科普视觉词典

仅在 `contentProfile.resolvedDomainPreset` 为 `ai-explainer` 或 `hybrid` 时读取。画风始终保持 `dense-whiteboard`；先匹配文案中的概念，再选择图形，不存在匹配时使用带准确 HTML 标签的通用节点。

## 固定色义

- 数据、资料、检索结果：`#3B9C95`
- 模型、算法、推理：`#8B5CF6`
- 重点、成本、延迟：`#F6C453`
- 风险、幻觉、失败：`#EF4444`
- 主体线稿和关系：`#171717`

## 概念映射

| visualKey | 概念 | 无文字线稿 | 典型关系 |
|---|---|---|---|
| `model-core` | 大模型、基础模型 | 中央核心、分层网络或芯片轮廓 | 输入→模型→输出 |
| `token-chunks` | Token、分词 | 被切开的连续小块 | 文本→Token 序列 |
| `embedding-space` | Embedding、语义向量 | 多个点落入二维坐标空间 | 内容→向量位置 |
| `vector-store` | 向量数据库 | 数据库圆柱与空间节点 | 向量→相似检索 |
| `retrieval` | 检索 | 放大镜从资料库挑出文档 | 问题→相关资料 |
| `rag-pipeline` | RAG | 问题、检索、上下文、模型四段链路 | 检索资料＋问题→回答 |
| `agent-loop` | Agent | 目标、计划、工具、观察组成闭环 | 计划→行动→观察→再计划 |
| `tool-call` | 工具调用 | 扳手或工具箱连接外部模块 | 模型→工具→结果 |
| `memory` | 记忆 | 分层便签或档案盒 | 历史信息↔当前任务 |
| `training` | 训练 | 数据批次进入模型并反复调节旋钮 | 数据＋误差→参数更新 |
| `inference` | 推理 | 单次输入穿过模型得到输出 | 输入→预测结果 |
| `context-window` | 上下文窗口 | 有容量刻度的长容器 | Prompt＋资料受容量限制 |
| `hallucination-risk` | 幻觉 | 信息缺口、错误答案和警示符号 | 不确定性→貌似合理的错误 |
| `api-exchange` | API | 请求卡、服务端、响应卡 | 请求→模型服务→响应 |
| `fine-tuning` | 微调 | 基础模型与特定数据合并成专业模型 | 通用模型＋样本→专用模型 |
| `multimodal` | 多模态 | 文本、图片、语音汇入同一模型 | 多种输入→统一理解 |
| `evaluation` | 评测 | 测试集、检查表和指标柱 | 输出→指标→比较 |
| `cost-latency` | 成本、延迟 | Token 计数器、硬币和计时器 | 用量→价格与等待时间 |
| `guardrail` | 安全、权限、护栏 | 盾牌、过滤门和人工复核 | 输入/输出→规则检查 |
| `generic-node` | 词典中没有的新概念 | 中性手绘节点或卡片 | 依原文关系连接，并使用准确 HTML 标签 |

## 使用限制

- 一个镜头只突出一个主要 AI 机制，其他概念作为从属节点。
- 同一概念在整条视频中保持同一图形和颜色，不在芯片、机器人、大脑之间随意切换。
- 品牌 Logo 不是概念图标；只有原文比较具体产品时才使用品牌名，并通过 HTML 呈现。
- Prompt、代码、模型名、参数、价格和数字必须由 HTML 技术组件呈现，不让图片模型绘制。
- 不用装饰性二进制雨、发光大脑或人形机器人替代真实技术关系。
