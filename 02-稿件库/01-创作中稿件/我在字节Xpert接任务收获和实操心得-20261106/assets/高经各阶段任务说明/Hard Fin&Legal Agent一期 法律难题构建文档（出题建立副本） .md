# Hard Fin\&Legal Agent一期 法律难题构建文档（出题建立副本） 

### **任务说明：**

# **具体需求：**

- 可以参考真实法律工作场景改造，或模拟一个完整的律所、法务、合规或争议解决团队项目。模型作答时必须综合参考所提供的不同模态文件；题目应围绕一个完整法律问题或相互关联的问题组设计，避免退化为单一法条查询或单点文书润色。**提供的文件不能是互联网上可以直接搜索到的文件。**

- 题目材料应当自洽，并包含必要的事实、时间线、主体关系、适用法律或冲突信息、商业目标及决策约束。不得要求模型自行编造影响结论的关键事实；对存在不确定性的事实，应要求模型列明假设、待核实事项及其对结论的影响。

- 文件类型包括但不限于：律师/客户邮件、内部即时通讯记录、合同及附件、公司章程或董事会材料、证据清单、法律意见书、尽调报告、Excel 台账、Word 文书、PPT、PDF、扫描件、图片、CSV、网页存档、法规/判例摘录、代码或隐私政策版本记录、Skills 文件等。只要模型可以下载并解析对应文件包即可；本次文件类型暂不包括音频、视频。

- 题目作答需要参考**至少10个文件，包含至少3个文件的类型**，**提供文件时请自行脱敏****，禁止强行凑文件类型，比如相似的内容一张jpg一张png，或者把word截图作为图片**

## **feature强制三选一****（可同时兼顾多个feature）****：**

### **带合同管理的mock系统**

- Mock 工具题是指使用模拟的企业内部系统或数据库完成任务。专家不需要开发真实工具，只需根据题目场景提供模拟数据，例如合同台账、合同文件和内部制度文件，并设计需要查询、读取或更新的数据操作。

- Mock 应具备一定复杂度，通常需要使用多个工具、填写较复杂的参数，或经过多次查询和判断才能完成任务。除 Mock 数据外，专家还需提交题目 Prompt、考点、标准答案及预期工具操作流程。后续将由技术团队把这些材料封装为可供模型调用的工具。

[什么是 Mock 工具题](https://bytedance.larkoffice.com/wiki/SnYFwEvKQiY6FokZGXOcIZtLnih)

### 带法律数据库

- 法律数据库的使用应具备一定复杂度，题目不能只要求查询一条法条或一个孤立判例。应要求模型围绕多个争点、主体、司法辖区或时间版本，批量检索法规、判例、监管规则或企业信息，并结合题设文件完成法律分析和交付。

    - 例如：比较不同时间版本的规则，检索多个相关裁判并分析其事实差异，或核验多个主体的工商、司法或监管信息。

    - 检索结果须与合同、邮件、证据等材料交叉验证，形成争点表、风险矩阵、法律备忘录、诉讼策略或合规建议；引用须可追溯。

    - 出题前确认数据库覆盖所需辖区、时间范围和文献类型，并支持相应访问、下载或引用方式；无法覆盖时，应明确可使用的官方替代来源。

- 目前可用的法律数据库包括企查查、天眼查，以及国内法规与法条检索。被测模型可使用这些工具查询企业信息和法律依据，Judge Model 则可据此逐条核验回答中的事实与法条引用是否真实、准确，因此题目可以设计得更加开放，不必局限于具有唯一标准答案的封闭题型。
天眼查链接https://www\.tianyancha\.com/ai

### 多轮问题（静态多轮、动态多轮或静态\+动态，5 轮及以上）

- **动态多轮**：鼓励使用可操作文件的 User Simulator 动态推进任务：模型阶段性产出后，用户可补充事实或证据、上传对方函件、更新系统记录、调整商业目标，并要求更新法律交付物。

    - 例如模拟庭前客户事实梳理：模型提出待核实事项后，客户补充时间线、聊天记录或合同版本，模型据此更新争点、证据缺口和策略。

- **静态多轮**：每轮向agent发的文字要求是固定的、提前设置好的

- 不得为凑轮次拆分问题；每轮须由新事实、证据、程序节点或业务决策触发，并用一句话说明任务为何确需多轮。
[多轮任务类型说明](https://bytedance.larkoffice.com/wiki/IpjPw64eZiM7imkzofgcwR0MnPe)

## **其他feature可选：**

- 海外题目：需具备真实的海外业务语境。题目中的研究标的、数据来源、文件材料、市场规则和交付场景均应来自海外市场，不能只是将中文题目或国内业务场景简单翻译成英文。

- User simulator：通过文字形式与模型进行动态交互，用户侧以 MCP 形式接入，并可根据任务需要配置多个不同角色或交互对象，共同推进任务。

- Skills \& Plugins：任务应要求模型在作答过程中深度调用多个 Skills 或 Plugins，而非仅做浅层、单次使用；不同能力之间应形成明确协同，共同完成最终交付。

- 提供自建/mock工具：可根据题目场景提供自建或 Mock 的工具环境，例如业务平台、专业数据库、邮件仓库或内部系统，用于模拟真实工作流和业务环境。

- Multi\-Agent：模型在作答时使用了多个agent，以模型作答的轨迹为准

- 长程任务：任务需包含多个相互依赖的执行阶段，模型需要持续维护上下文和任务状态，并经过信息获取、分析处理、中间产物生成、反馈调整和最终交付等完整链路。模型调用工具的轮次在50轮以上，以模型作答的轨迹为准

- **难度要求：如果题目难度不够最多返修两次，返修两次后无法满足难度要求本题作废。**

    - Claude opus 4\.8 \+ GPT5\.5 在claude code or codex下按考点打分准确率低于60%。 

- **提交格式：**prompt\+文件zip包\+考点（详细作答思路，人类专家该如何作答）\+标准答案
