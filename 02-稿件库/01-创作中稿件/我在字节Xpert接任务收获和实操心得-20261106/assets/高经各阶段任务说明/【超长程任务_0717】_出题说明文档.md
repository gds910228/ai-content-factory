## 背景：

本任务旨在收集一批真正满足“**超长程任务**”的题目。长程任务指：为了完成一个明确、复杂、可验收的目标，模型需要经历多个相互依赖的执行阶段，并在过程中持续维护上下文状态、整合多源信息、产出中间结果、进行校验修正，最终形成结构化、可复核的交付物。超长任务是长程任务中，显著存在持续推进时间长，存在多轮路径调整、版本迭代和多层验收这几类特征的任务。同时，尽量增加 上一版题库中MA子场景覆盖不足的标签，包括同步 vs 异步、收集/汇合时机、演进任务管理、动态增派/终止、冲突消解/去重、缺口识别与补派的题目。

- 超长程任务：超长程不是“材料多”或“产物长”，而是要同时满足：

| 维度       | 要求                                                       |
| -------- | -------------------------------------------------------- |
| 执行步骤     | 至少 9 个相互依赖的宏观阶段，并出现路径调整、回退或多条执行分支。                       |
| 状态维护     | 至少 10 个有效中间产物，覆盖 3 个以上里程碑，并存在版本迭代、回退或中断续接。               |
| 校验难度     | 至少 3 个独立验收关口，并完成多次修正循环直到收敛。                              |
| 资源消耗     | Agent 主动执行时间优先 2 小时以上，超长候选最好超过 4 小时。用户空等、权限阻塞、未来定时等待不计入。 |
| Trace 证据 | 必须能从 Trace 中定位阶段、产物、失败、修正、重跑和验收动作。                       |

## 标注专家任务

- 出题形式：单轮/多轮均可

- 建议出题方向

| 出题方向    | Prompt 参考描述                                                                                       | 主要验证点                               |
| ------- | ------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 长耗时后台   | 专家设计一个包含真实长耗时执行环节的任务。Prompt 中应要求 Agent 在等待运行、构建、爬取、渲染、搜索或批量评测期间，继续推进可并行的主线准备工作，并在后台结果完成后合并到最终交付。  | 是否能识别适合后台化的环节；是否减少用户等待；后台失败后能否恢复。   |
| 克制不派    | 专家设计一个高度依赖全局一致性的任务。Prompt 中应明确前后文、术语、风格、逻辑链或法律/学术/叙事口径必须统一，过度拆分会造成冲突，因此需要评测 Agent 是否会克制委派。        | 是否能判断“不该拆”；是否能保持全局约束；是否避免多个子结果互相打架。 |
| 冲突消解/去重 | 专家设计一个**多来源信息不一致的任务**。Prompt 中应要求 Agent 识别不同来源之间的重复、冲突、时效差异和证据等级，并给出最终采用口径与舍弃理由。                  | 是否能发现冲突；是否能去重；是否能给出可信的证据优先级和最终结论。   |
| 缺口识别与补派 | 专家设计一个**初轮处理很容易漏字段、漏对象或漏证据的任务**。Prompt 中应要求 Agent 先产出初版，再自查覆盖缺口，针对缺口补充检索、补派处理或重跑局部任务，最后输出补齐后的正式版。 | 是否能主动发现漏项；是否会针对缺口补派；补派结果是否真正进入最终产物。 |
| 收集/汇合时机 | 专家设计一个多条子线进度不同的任务。Prompt 中应要求 Agent 判断哪些子结果可以先用于搭框架，哪些关键结果必须等待后才能定稿，避免过早汇合导致错误，也避免过晚汇合导致低效。       | 是否能判断汇合时机；是否能边收集边推进；关键结果回来后是否会更新结论。 |
| 动态增派/终止 | 专家设计一个探索过程中可能出现新线索或无效方向的任务。Prompt 中应要求 Agent 根据中间发现动态增派新的核验/处理任务，并及时终止重复、低质或无效方向。                 | 是否能根据中间结果调整计划；是否能增派必要任务；是否能停止无效分支。  |
