# 高经济价值任务难度突破指南

# 一、分数、轮数和时长分别靠什么

| **指标**     | **要求**                                         | **靠什么**             |
| ---------- | ---------------------------------------------- | ------------------- |
| Sota模型得分率  | 不高于45分，必须达到                                    | Prompt里埋难点，考点把难点查出来 |
| Sota模型执行轮数 | 不少于55步，和运行时间满足一项即可                             | Prompt安排的工作量        |
| Sota模型运行时间 | 超过45分钟，和执行轮数满足一项即可 | Prompt安排的计算量        |

轮数和时长好理解，模型要干的活多，轮数自然就上去了。十几份文件要一份份打开，几千行记录要一条条处理，排程要真求解，代码要真跑测试，七八份交付物要一份份写，写完还得回头对数，这些都是实打实的步数。这部分主要靠Prompt来设计。

分数要复杂一些。模型答错了，考点却没查那个地方，分数照拿；考点写得再细，材料里没有会让它出错的东西，它也能拿满。分数得靠Prompt和考点配合：Prompt里放进容易做错的地方，考点专门去查这些地方。

**核心原则：**以上两件事要同时设计在一道题目中。只堆工作量的题，模型老老实实干了六十轮，每一步都没错，分数还是很高；只埋难点的短题，分数压住了，二十几轮就交卷了。比较好的做法是把难点藏在模型必须一条条处理的明细里，活不干完就碰不到难点，碰到了还得认得出来。

**选题判断：模型替你把这件事做完，你愿不愿意为结果付费。**值得付费的任务，背后一般都有一个人要在某个时间前拍板，比如这批备件订多少，这份合同能不能签，这个版本能不能上线。围绕这个决定出题，题目就有了方向，考点也有了对错。

# 二、用Prompt把轮数和时长做上去

思路很简单：让模型必须一步步地做，而且步与步之间有先后，没法合并。

## （一）好的做法

1. **附件给原始的，别给整理好的。**真实工作里的材料是散的：系统导出一份CSV，财务给一张Excel，邮件里一个说法，会议纪要里又一个说法，最后还有一份盖章的正式文件。把它们按原样分开给，格式也保留原样，模型每换一种文件就得换一种读法。你要是先替它汇总成一张干净的表，它三五轮就读完了，里面的矛盾也看不到。

2. **要求每条记录都有结果。**让模型逐笔、逐户、逐个SKU给结论，没有需求的行也要留着，汇总数要能对回明细。明细的量控制在人工一条条看不完、写脚本又得先把规则弄懂的程度，几百行到几千行都可以。

3. **要求真的跑起来。**排程要真求解，代码要真跑测试，结果要能从空文件夹重新生成，并留下命令和输出。没跑的就写没跑。这一类要求最能拉长运行时间。

4. **交付物分成几份，数字要对得上。**给审批人的报告、给执行岗位的清单、给财务的底表、给后续跟进的待确认事项表，各写各的，内容不能互相抄，数字必须一致。题面里可以直接写出哪些数必须相等，比如需求减库存等于缺口，缺口加安全量等于下单量。

5. **前后有依赖，情景要重算。**先定口径，再算明细，再出方案，最后做压力情景和执行安排，前一步的结果就是后一步的输入。压力情景要求重新算一遍，不许把主方案按比例打个折了事。

6. **最后留一步自查。**要求模型换一种算法把核心数字再算一遍，或者做一张跨文件的对数表，对不上就回源头去改，不许在结果页上直接改数。

## （二）大致算一笔账

按一般的作答路径粗算：15份左右不同格式的附件，读下来要十几二十轮；清洗、关联、处理异常十轮上下；核心计算十轮上下；三个压力情景各重算一次，六轮左右；七八份交付物，一份一两轮；最后对数返修再来五到十轮。加起来五六十轮。因此，如果题目附件只有两三份、只交一份报告的题，内容再难也很难到50轮。

## （三）不好的做法

1. **靠硬性规定凑轮数。**规定必须按固定步数逐步输出，每一步都要重新打开同一个文件，每做完一步单独发一条进度消息，要求派子代理分头做，要求把全部资料调研一遍或者写够上百页。消息条数确实多了，题却没有变难，分数压不下来。项目说明里写了，靠扩大范围做长的任务不收，质检很可能判成凑量。

2. **把几件不相干的小活拼在一起**。每件都要做，轮数也上去了，但它们之间没有共同的目标，也谈不上谁依赖谁，不符合真实工作场景，而且这些小事彼此独立，难以有效压低分数。

# 三、用Prompt和考点把分数压下来

## （一）先估一下送分的比例

写考点之前先估一下：**格式对不对、结构全不全、常规的加减乘除、常识性的结论，这些Sota模型基本都能拿到。你可以把SOTA模型想象为一个刚985毕业的实习生，常规、理论性是考点都难不倒他。**如果它们的内容加起来接近总考点的一半，难点埋得再好也压不到50分以下，这类考点要少放。

## （二）在Prompt里放进容易做错的地方

> 真实工作里让人出错的地方，模型一样会错。

1. **材料之间打架。**同一张订单有草稿和正式版，同一个客户在两个系统里编码不一样，群里有人凭印象报了个数。光放矛盾还不够，还要给一个判断依据，告诉模型以谁为准，比如签发的优先于草稿，合同优先于会议纪要，截止日前批的优先于事后补签的。没有依据，这道题就成了开放题，考点判不了对错。

2. **同一个数，口径不一样。**含税和不含税，原币和人民币，下单金额和实付金额，月报数和年报数。模型最常见的错法是拿来直接相加。

3. **表面上的指标会骗人。**平台后台的ROI、供应商报备的产能、全月总工时，看着够用，拆到每周、每个班次，或者换成实际利润一算，就不够了。比如报备产能只是单班日产，乘上工作日、开班数和良率之后，才是真正的月供应能力。

4. **顺手的做法走不通。**预算、产能、比例上限、起订量几条限制同时卡着，按单价排序、先到先得、按比例分摊这些顺手的办法，总会违反其中一条。压力情景也一样，可用额度砍掉一半，方案就得重新选，按原方案打五折是错的。

5. **时间和状态分不清。**题面写清楚截止到哪一天，之后才到的更正只能用来解释偏差，不能拿来改当时的结论。待审批不等于批了，开了票不等于钱到了，测试没跑不能写通过。模型为了让方案看起来完整，很喜欢把没定的事写成定了的。

6. **有人提了错误的要求。**老板要求所有客户一律打八折，前任的结论有一部分已经被推翻，业务方坚持报表亏损就关店。题目要求模型逐条回应、用数说话，它就得在顺着说和拿数反驳之间做选择。

7. **看着有问题，其实没问题。**某个监测字段按规定本来就不填值，某条专用条款写的是按通用条款执行，这些都正常。模型很容易什么都标成风险，放一两处这样的地方，就能把“全部不通过”式的答卷筛出来。

## （三）埋难点时要注意

1. **难点要藏在原始明细里，题面上别点破。**题面一写“附件3第12行是重复记录”，模型照着改就行，这个点就废了。

2. **题面上写“不得直接相加”“不能简单平均”这类提醒**，基本不增加难度，模型会照做。真正起作用的，是材料里确实有会让它犯错的东西。

3. **公式、参数、换算关系不要直接给**，只给业务规则和正式文件，让模型自己推。

材料写完，自己先用最顺手的办法做一遍。顺手的办法就能得出正确答案，说明这道题的判断部分没有难度，还得再加限制或再埋点。

## （四）考点要把难点查出来

**考点写得粗，难点就白埋了！！！**拿口径那一处来说，考点写成“考虑了含税与不含税的差异”，模型提一句就能拿分；写成具体的数，它算错了就拿不到。下表里的数字只是举例。

| **难点**     | **容易被糊弄过去的写法** | **能查出错的写法**                                        |
| ---------- | -------------- | -------------------------------------------------- |
| 口径不一样      | 考虑了含税与不含税的差异   | 三季度不含税收入为1284\.6万元，误差不超过0\.1万元；直接用含税数1451\.6万元的不得分 |
| 情景要重算      | 对压力情景做了分析      | 额度减半后入选的是A、C、F，不含B；按原方案等比例缩减的不得分                   |
| 状态分不清      | 区分了事实和计划       | 三项待会签的采购在执行清单里标为“待确认”；标成“已批准”的不得分                  |
| 看着有问题其实没问题 | 识别出了材料中的异常     | 第17条“按通用条款执行”判为没有改变默认安排；标成风险条款的不得分                 |
| 执行安排       | 给出了执行建议        | 停产切换写明负责岗位、完成时间和回滚条件；缺一项不得分                        |

写考点时还有这些讲究：

1. 一条考点只查一件事。几个并列的计算结果分开写，别合成一条。

2. 每个难点至少对应一条考点，考点重心往这些考点上倾斜。

3. 对常犯的错设不得分条件，比如把没确认的写成已完成，什么都判成不通过，替决策人拍了本该由他拍的板。

4. 上游错一处会连带下游好几条考点丢分时，确认每条查的是不同的东西，并在标答里写清楚连带关系，方便质检判断是不是重复扣分。

5. 能唯一确定的结果，尽量设计成唯一，打平时怎么取舍也写进题面。开放一些的部分，用“必须写到哪些点、不能出现哪些错”来判。

6. 文件名、字段、单位、小数位、允许的误差都写进题面。要求定死了，考点才好判，模型也没法靠格式上的自由发挥拿分。

7. 考点数量建议删掉简单的考点，保留和增加高难度考点，对考点进行赋分，有难度的考点给出更高的权重，比如一些数值类考点。

**考点怎么写：8 条注意事项**

| 重要原则                                                                                                                                                    | ❌ 常见错误写法                                             | ✅ 正确写法                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **1. 原子化**一条考点只考察一个点，不要把好几个考察点塞进同一条里                                                                                                                    | "模型要正确计算 ROI 并分析 ROI 偏低的原因"——计算对了但分析错了算对还是错？一条里塞了两个点 | 拆成两条：①"模型应计算出 ROI 数值为 150%，误差不超过 ±5%"；②"模型必须指出 ROI 偏低的至少两个原因"                           |

| **3. 客观可判定**每条考点都能根据模型回复明确判断对或错，不能有<u><span><font face="Arial">“</font><font face="等线">是否</font><font face="Arial">”</font></span></u>或"好不好""够不够"这种主观判断 | "模型的分析要全面深入，有洞察力"——什么叫"全面"？什么叫"有洞察力"？判分系统没法判断        | "模型回复中必须同时包含客流数据、营收数据、投诉数据三个维度的分析，缺任何一个则不得分"——有没有三个维度，一眼就能看出来                           |
| **4. 具体不笼统**明确指出模型回复里应该出现什么具体内容，不要只说"要给出建议""要做分析"                                                                                                       | "模型要给出合理的运营建议"——什么建议？几个建议？建议里要包含什么？                  | "模型回复应明确给出至少 3 条针对节假日客流高峰的分流建议，每条建议包含具体执行措施和责任岗位"                                       |

| **7. 不冗余重复**不要多条考点反复考察同一个内容，每条考点考察一个不同的点                                                                                                                | 考点 1："模型回复中必须包含预算"；考点 2："模型要有预算明细"——两条其实考察的是同一件事，重复了 | 考点 1："模型回复中项目决算总金额应为98,650元"；考点 2："模型回复应明确指出人员费用为38,500元"；考点 3："模型回复应明确指出场地费用为24,800元"。 |
| **8. 数据带单位和容差**考察数据计算时，必须写明单位和允许的误差范围，不要只说"要正确"                                                                                                         | "模型计算的客单价要正确"——正确是多少？单位是什么？差一块钱算错吗？                  | "模型回复中计算的客单价应在 150-180 元之间，单位为元/人，超出范围即不得分"                                             |

一句话总结：好的考点 = 能判断对错 + 说清要什么 + 一个点一条 + 答案准确。写完每条考点，自己读一遍，问自己："能否只根据我写的这份考点就能判断出模型的回复正确与否"如果能，这条考点就合格了。



## （五）标答和作答思路

标答最好自己独立核一遍。作答思路里把每个难点交代清楚：在哪一步发现，怎么处理，做错了会得出什么数。质检主要靠这部分判断考点有没有道理。

# 四、出题顺序和试跑后的调整

**1．选一个真实的决定。**找你岗位上经常发生、做错了会有损失的一件事，比如备件该订多少、合同能不能签、这批贷款要不要调分类。把前面的数据整理、口径确认和后面的方案比较、执行交接一起放进来，别只做中间一小段。

**2．把交付要求定死。**要交哪几份文件，每份叫什么名字，有哪些字段，保留几位小数，结论只能从哪几个选项里选。

**3．列一张只给自己看的难点清单。**每一行写清楚：难点埋在哪份附件的哪几条记录，正确做法是什么，模型可能怎么错，错了会影响后面哪些数。一道题一般列8到15个，尽量覆盖上面说的不同类型。

**4．照着清单丰富材料。**按来源系统分文件，把难点放进明细，给出以谁为准的依据。

**5．自己用顺手的办法做一遍，确认真的会踩坑。**

**6．写考点、标答和作答思路，考点和难点清单逐条对上。**

**7．跑一遍Sota，看分数、轮数和时长，没达标就对照下表改。**

| **跑出来的情况**    | **一般是什么原因**                    | **怎么改**                                      |
| ------------- | ------------------------------ | -------------------------------------------- |
| 得分超过50分       | 题面点破了难点，材料太干净，送分考点太多，考点写得太粗    | 把提示从题面拿掉，难点放回明细；多放几处版本冲突和口径差异；压低格式分；考点改成具体数值 |
| 模型错了却没扣分      | 考点没查到这个地方                      | 对照难点清单补考点                                    |
| 轮数够了，分数还高     | 活很多，但难点不在模型必须处理的地方             | 把难点挪进要逐条处理的明细，让汇总表和明细对不上                     |
| 轮数不到50步       | 附件少或者已经汇总好，只交一份报告，不用真跑，情景能按比例缩 | 换成各系统的原始导出；拆分交付物并要求对数；加入必须运行的求解或测试；要求情景重算    |
| 时长不到40分钟      | 计算量小，要逐条判断的对象少                 | 扩大逐条判断的范围，加入需要枚举或求解的环节                       |
| 分数很低，但模型根本没法做 | 材料不够，缺判断依据                     | 补材料和判断依据                                     |

改的时候动材料和结构，别去加凑轮数的硬性规定。

# 五、不要出的题

1、按章节填空的报告。题面列好一二三，材料很干净，模型照着填就是高分。

2、拼盘题。几件不相干的小事凑在一起。

3、离不开外部条件的题。要登录真实平台、用真实账户或者抓实时数据，光靠给的材料开不了工。

4、换壳题。同一个题面结构换个公司名、换个行业就算一道新题，项目会查重。参考素材可以学思路，结构和写法要自己来。
