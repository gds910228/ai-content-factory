3. 生成附件：按《出题通用规则》第二节目标（份数、原始件体量）和红线（固定种子脚本生成、保留原始导出格式、按来源系统分文件、不预先汇总、保留原始冲突并只写仲裁依据、中性备注、数据脱敏）执行；每份附件须承载至少一个难点或必要证据，并含少量与结论无关的真实业务噪声；所有附件围绕同一个决定，且无需外部网络或私有环境。
4. 写题面：用真实委托人的口吻（按交办新人工作的逻辑）写背景、目标和交付物，不写解题步骤，遵守红线第 2 条。
5. 交付物设计：要求模型产出 6–8 份不同读者的文件（给审批人的报告、给执行岗位的清单、底表、待确认事项表、对数表等），数字必须一致；核心数字要求换一种算法复核并出具对数记录；压力情景换参重算；写入红线第 4 条的真跑要求，并使测算链可参数替换重跑 ≥ 10 次。
6. 重测与步数预算：做顺手做法重测和称职专家做法重测（见《出题通用规则》第五节），并分项估算步数；合计低于 55 步先改结构。
7. 写考点、作答思路、标准答案：遵守红线第 7 条、第四节细则和第二节目标（含结论考点的依据要求与半开放部分的规定）；独立核算全部标答数值，核对引用的文件名、ID 在附件中真实存在；完成闭环验证（标答每个结论在附件中有可定位的证据），并列出需人工复核清单（红线第 10 条）。

【输出要求】

1. 所有产物写入当前文件夹/v1，创建 CHANGELOG.md，并按《出题通用规则》第七节整理交付格式。
2. 最后给出结构自评（不得预估得分）：送分权重占比、三类考点权重分布、决策链节点数与结论翻转型节点数、含依据要求的结论考点数、半开放权重占比，并指出最可能不达标的一项和对应的加固建议。

### 二、返修提示词（首轮后加固 / 平台评分后返修）

（此处粘贴：删除题面所有透题提醒，包括对数锚点、行数等显性提示；把具体逻辑关系放进输入附件让模型自己发现，在考点中考核隐性考点；附件保留原始冲突并给出仲裁依据；删除简单考点，保留并增加高难度考点，给数值类等难点考点更高权重；考点越严格越具体越明确，缺什么不得分都写进考点，且一条考点只说一件事。）

* 档 3：难度分已达标，但时间和步数两项都不达标 —— 只增加有效工作量。

加固情形直接做体检。无论哪种情形，诊断内容都包括：

1. 题面透题：逐句检查，标出红线第 2 条列出的所有透题类型；并扫描全部附件，标出替模型做判断的备注和与题面互为镜像的教练式提示。

7. 材料是否真的缺判断依据（分数很低但模型无法做的反面风险），若有则先补依据。

二、题面（档 2 必做；档 1 先做；加固情形视体检而定）

三、附件（档 2 必做；档 1 与加固情形视诊断而定）

* 对"无效难点"重新设计，放回需要逐条处理的明细里；补 2–4 处新难点，按第三节类型优先选跨系统对齐连锁、反向陷阱等，并满足判断类难点比例。

### 三、本地自测提示词（由我手动执行，不交给出题 Agent）

建议使用 Kimi K3、Qwen 3.8 或 GLM5.3-FLASH 自测。自测目标 ≤ 35%（内部线 45%，平台线 50%）。最终质检所用模型强于本地自测模型，自测通过也要留余量；GLM5.3-FLASH 偏弱，仅用于筛掉明显过易的题，不作为余量依据。答题与评分必须分窗口进行，操作如下：

1. 答题窗口：新开会话，只提交题目 Prompt 和全部问题附件，不上传标答、考点和作答思路。
   第一步给模型：**忘掉上次解题过程和评分结论，不要查找记忆**，请完成以下任务并交付全部文件。题目 Prompt 和附件一并上传。
2. 评分窗口：另开新会话（优先换一个与答题不同的模型），提交题目 Prompt、答题模型的答卷和交付文件、标准答案（文本及附件）、考点和作答思路。不要把标答和评分标准投喂给答题的会话。
   第二步给模型：**请依据考点，结合标准答案（文字和附件已上传），并将作答思路作为弱辅助，对上传的答卷逐项评分。数值类考点必须落入容差才得分，不得因"思路正确"给分；状态、集合、字段类必须完全一致；部分正确一律 0 分（半开放部分按考点中写明的要素和分级判分）。对每一条给出答卷中的原文证据，没有证据则不得分。评分完成后，列出你认为可能给得偏松的三条，并按严格口径重新给分。最后汇总得分率、答题的assistant message 条数、工具运行轮次和运行时间。**

自测协议：

* 同一版本至少跑 3 次，取平均；记录每个考点在 3 次中的通过次数（3 次都通过的视为送分，3 次都失分的才是稳定难点）。
* 评分提示词保持固定，并使用独立窗口、尽量换模型评分；自测与平台机评可能有出入，最终以平台机评为准。
* 同时记录原始分和严格复判后的分，两个数一起看。
* 只改考点时，用同一份旧答卷按新考点重判，不必重跑；改了题面或附件才需要重新作答。对比不同版本时，各版本在各自对应的考点下评分，不直接比较单次分数。
* 自测得分剖面用来决定删留：删"模型拿得到"的考点会降分，删"模型拿不到"的考点会升分，依据是得分剖面而不是主观感觉。

### 四、本地自测后优化提示词

（上传：《出题通用规则》《高经济价值任务难度突破指南》。）

请先阅读《出题通用规则》和《高经济价值任务难度突破指南》，再读取当前文件夹中的最新版本（以 CHANGELOG.md 中"当前推荐上传版本"为准）。规则以《出题通用规则》为准。

【自测情况】

* 使用模型：GLM5.3-FLASH 最高推理模式。
* 方法：答题窗口新开会话，仅提交 Prompt 和全部附件作答；评分窗口另开新会话（优先换模型），提交答卷、标准答案（文本与附件）、考点和作答思路，逐项打分并汇总得分率。
* 本地得分率：XX%
* 作答轮数 / 时长（如有）：XX / XX
* 模型的逐项评分与反馈：XXXXX
* 补充返修方向（如有）：XXXXX

【本轮优先级（必须遵守）】

1. 唯一目标：降低同一模型的得分率。清晰度的提升只能通过补充"事实与条款原文"实现，不得补充"结论、推导路径、指向性措辞"。
2. 实测失分的考点是有效难点，保留并复制其类型。
3. 实测通过的考点，无论作者当初如何标注（含"数值类难点"），一律按送分对待。
4. 不得为了消除失分点的歧义而降低其难度。区分两类歧义：不可从材料推导的假设，处理方式是取消该考点计分，或补充事实依据，不得写入答案线索；正确口径能从材料推导且公平的歧义，属于合法难度，保留。
5. 单点数据清洗陷阱（重复、空格、时区、混合时间戳、单位混用）实测已被模型处理好，不再作为主要难度来源，仅保留为交付质量要求；但无映射表的跨系统对齐加状态修正、并连锁到下游多项结果的陷阱，实测有效，应保留并增强。
6. 局部改的第一步先清除题面透题，再动考点。

【第一步：拆解自测结果（先不写入任何文件）】

1. 逐条列出每个考点及权重，标明实测通过或失分，计算"实测通过权重占比"。
2. 对通过的考点分簇（如成本核算、激活统计、回收效率、格式交付），标出哪些簇是纯执行（计算、清洗、复述条款、格式）。
3. 对失分的考点分型：
   * 判断型：条款或红线与经济性的冲突、时限倒推、统计窗口锚定、清单纳入标准、约束是否贯穿全程、折中路线与硬边界、跨系统对齐连锁、反向陷阱、跨时间版本规则匹配、事实与假设混淆。
   * 路径型：结论正确但依据或传导缺失、错误（依据要求不满足）。
   * 表达型：事实已掌握但未显式写出构成或汇总。
   * 口径歧义型：题面和附件未写明假设，导致合理的不同口径（区分"不可推导"与"可推导且公平"）。
   * 评分偏差型：评分过松或过严。
4. 同一对话自评容易偏松。按"数值落入容差才得分、状态集合字段完全一致才得分、部分正确 0 分"的严格口径重新评分，给出严格得分率与原得分率的差；同时标出"方法对但数值没出现"的方法分。
5. 逐句检查题面，列出仍然存在的透题内容（红线第 2 条所列类型）；并扫描全部附件，标出替模型做判断的备注和与题面互为镜像的教练式提示。
6. 找出"模型发现并处理对了"的难点和"模型根本没碰到"的难点。

【第二步：结论与权重迁移预算（先给结论再改）】

1. 严格得分率 ≤ 35% 且大权重考点均为实测失分类：保持当前版本，不创建新版本。
2. 严格得分率在 35%–60%：局部改。先清题面透题与附件镜像提示，再改考点，必要时补 1–2 个难点。
3. 严格得分率 > 60%：必须重构权重，禁止只修补失分点；按层分步验证。
4. 计算迁移预算：需要从"实测通过的执行类考点"迁出的权重 ≥ （严格得分率 − 30%）× 总权重，并迁入新增或升级的判断型考点。写出迁移前后的权重分布（执行类、判断型、表达型、送分类）。
5. 明确列出本轮不改动的内容及理由。

【第三步：返修（写入新版本目录）】

一、考点

* 将实测通过的执行类考点按簇合并，每簇保留 1 条（权重 1），保留"对数一致"的底线检查，其余权重迁出。
* 保留所有实测失分的判断型、路径型和表达型考点，权重不降。
* 新增判断型考点，每条写明：唯一结论、依据条款或事实（指出在哪些文件）、模型最可能给出的错误结论及其不得分条件；并在每条新增结论考点的通过条件中写明依据要求。

二、题面

* 删除全部透题内容，遵守红线第 2 条；不得在题面加入"红线""禁止"等指向性措辞。

三、附件

* 新增判断型难点，每个满足：正确结论必须由 ≥2 份文件组合并结合一条硬条款或红线才能推出；存在一个模型自然倾向的"合理替代方案"（经济性、惯例、折中、从宽理解），该方案会违反这条硬条款；任何一份文件都不直接写出结论。

四、工作量（仅当轮数和时长都明显不足）
