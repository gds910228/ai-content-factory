## 二、核心内容总结

### 最有价值的 3 个核心观点

1. **"少即是多"在 Prompt 工程里是物理定律，不是鸡汤——注意力有固定带宽，越堆"严禁"越分散注意力，1500 行→300 行遵循率反升**
   来源：[[01-选题库/02-用户痛点选题池/删掉80%的Skill，Agent反而更听话了.md\|删掉 80% 的 Skill]] 04 节 + 恶性循环定稿 + [[01-选题库/01-热点选题池/2026-07-30 Prompt Engineering的下一站--从写好一句话到设计一个系统.md\|PE 下一站]] 选题
   这是本周整个选题矩阵的**总纲性主张**。源素材用 git 历史量化了膨胀过程（400→650→1000→1500 行，40 次修复追加约 1100 行，真正新知识仅 300 行、重复 800 行），精简回 300 行后遵循率反升。本周发布的恶性循环文更进一步，用"99% 机械拆分乖乖执行、最后 1% 崩在 SSE"的反直觉对照坐实了这条定律——**SSE 不是被 AI 弄崩的，是被膨胀的铁律喂崩的**。结论把"严=稳"的直觉连根拔起。

2. **AI"不听话"的根因不是强调不够，而是 4 个结构性机制：U 形注意力 / 静默择一 / 粉红大象 / 上下文淘汰赛**
   来源：删掉 80% 源 01 节 + 恶性循环定稿 04 节
   四个机制各有硬数据支撑：Lost in the Middle 的 U 形曲线（开头约 73% 遵循率，中间下降 30–50%）、指令冲突静默择一（顶级模型失败率 23–47%）、否定指令反而激活被禁概念的粉红大象效应、多轮对话规则被挤出窗口的淘汰赛。两个最反直觉的洞察：**"位置决定优先级，不是规则重要性决定优先级"**，以及**"越说禁止，模型越需要先激活被禁内容"**。这把"模型不听话"从玄学变成可工程化诊断的结构问题——也是本周 6 篇选题能各自独立成篇的理论底盘。

3. **"自动化移除了天然刹车"——让 AI 自动改 Prompt 是最隐蔽的膨胀陷阱**
   来源：删掉 80% 源 02 节 + [[01-选题库/03-行业干货选题池/2026-07-30 让AI自动改Prompt，它把规则写了8遍--自动化的膨胀陷阱.md\|膨胀陷阱]] 选题
   这是本周**竞争度最低、最被低估**的洞察。自动修复工具几乎只做"追加新规则"而不通读全局、不改已有、不分析根因——它选了最安全的路径。关键反直觉点：**人手改 Skill 时，人的懒惰反而是膨胀的刹车；自动化把它拆掉了**，每次 badcase 都被勤勤勤恳恳转化为新规则，同一规则最终散布 8 处。解法是给自动修复加 4 个刹车（行数预算/语义去重/单次追加上限≤20 行/定期压缩），并类比为代码"技术债管理"。该角度几乎无人系统讨论，是高壁垒差异化方向，且可普适映射到 RAG 知识库、规则引擎等更广场景。

   本周同时入池的 [[01-选题库/03-行业干货选题池/对Loop Engineering的思考.md\|对 Loop 的思考]] 提出"**控制论 = 通过负反馈机制收敛目标函数**""**TDD 的价值是把需求翻译成反馈信号**""LLM 是概率模型、分治后六次叠加概率就近 50%（抛硬币）"——这恰好给 Prompt 工程的"少即是多"提供了 **Why**：因为单次概率不可靠，必须靠 Loop 的负反馈去修正。而 Graph Engineering 的 Verifier/Maker-Checker/干净上下文，与 Prompt 工程的 U 形注意力/静默择一是**同一对抗熵增逻辑在两个尺度的展开**（单次对话 vs 多节点系统）。可产出进阶长文《从 Prompt 瘦身到 Loop 收敛：对抗熵增的两层防线》，把 [[2026-07-01 AI Coding 的底层框架：一切优化都是在对抗熵增]]（上期已识别的根框架）作为 Why 顶层，Prompt 工程=单次层、Loop=迭代层、Graph=系统层，串成一条完整演进链。
